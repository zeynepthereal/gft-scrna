INTERPRETATION
- Preprocessing is exact: 50,518 cells x 24,111 genes, identical to the paper. The loading/filtering/
  normalization path is deterministic and platform-independent.
- All deviations come from Leiden cluster boundaries. The same 13 samples give 27 clusters;
  Macrophage and Fibroblast counts match exactly, B cell within 3, Epithelial within 33 (0.15%).
  The largest deviation is NK vs T (-279 NK / +261 T): a cluster on the NK/CD8-T border is split
  differently. That is the part of the embedding a Leiden run most easily cuts in a different place.
- Likely cause: Leiden (leidenalg + igraph) partitions depend on the random seed AND on the
  library versions and floating-point details of the kNN graph (UMAP-style connectivities / PCA
  solver on arm64 vs x86_64 Windows, numpy/scipy BLAS). The original environment's versions were
  not recorded, so the original partition cannot be reproduced bit-for-bit. Changing only the seed
  (0 vs 42) on the same Mac graph moves ~0.2% of labels and gives a similar
  (not identical) spread, e.g. Endothelial 124 with seed 42, which matches the paper exactly.
- Paper-level claims are preserved: Patient1 residual ratio 3.67x vs 3.64x, Patient2 1.39x vs
  1.38x; epithelial counts differ by <=11 cells (<0.35%).
- Nothing was tuned to match. The saved h5ad uses the original script's settings
  (random_state=0, scanpy default), not the random_state=42 in the task spec. See the sensitivity block.
